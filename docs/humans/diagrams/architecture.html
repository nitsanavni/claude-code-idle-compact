idle-compact · architecture

A small, testable core between two thin layers

Claude Code tells the mod when turns start and end. A thin wiring layer passes that on to the core, which makes every decision. The core reaches the outside world only through small wrappers, and in tests those wrappers answer from memory instead.

All the logic sits in core.ts and config.ts, so tests drive the real core over stand-in infrastructure, with no mocks.

How to read this diagram

Read it top to bottom: events come in from Claude Code at the top, decisions are made in the middle, and the bottom is where the mod touches the outside world again.

Each box is a file or a piece of one; its color says what kind of code it is:

  • Claude Code — the host program and its $ interface
  • Wiring — connects events and tools to the core
  • Logic — pure decisions, fully unit-tested
  • Infrastructure — one small wrapper per outside thing
  • Dashed box — a stand-in that only exists in tests.
  • Arrow — calls or hands over to; the small label says with what.
  • Dashed arrow — the same call, answered by the test stand-in instead.
  • Dashed frame — boxes that live together in one file.
