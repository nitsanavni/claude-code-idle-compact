idle-compact · timer

The timer, from turn to compaction

Every time a turn ends the mod starts a countdown, and every new turn cancels it. If the countdown runs out, the mod looks at the context size and compacts only when it is worth it. Claude can also ask for a compaction right after the current turn.

After any outcome the timer rests until the next turn ends. Settings are read again at every start and at every check, so changes apply on the next turn.

How to read this diagram

Each pill is a state the timer can be in; the mod is in exactly one of them at a time. Each arrow is a way to move between states, labelled with what makes it happen.

  • Resting — no countdown
  • Counting down — idleSeconds
  • Checking — how big is it?
  • Compacted — toast, log, push
  • Skipped — too small to bother
  • Dry run — reports, no change
  • Queued — waits for turn end
  • Filled dot — where things begin: a session starting, or Claude calling a tool.
  • Arrow — a transition, with its trigger written next to it.
  • Dashed arrow — a transition you start on purpose, not by waiting.
  • Loop — the state starts over: the countdown begins again from the top.

Only the main conversation moves the timer. Turns run by subagents neither start nor stop it.
